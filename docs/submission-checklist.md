
# Kiroween 2026 — Submission Checklist

Keep this file updated as the project progresses. This is an operational checklist, not a substitute for rereading the official rules and FAQ before submission.

Official sources:
- Rules: https://kiroween.devpost.com/rules
- FAQ: https://kiroween.devpost.com/details/faqs

**Submission deadline:** December 4, 2026, 2:00 PM Pacific Time  
**Nigeria time:** December 4, 2026, 11:00 PM WAT

## 1. Eligibility and project

- [ ] Confirm the project was created within the eligible submission period.
- [ ] Confirm the project is a new project and not an ineligible pre-existing submission.
- [ ] Select the category: **Costume Contest**.
- [ ] Confirm the app clearly satisfies the category's haunted/spooky theme.
- [ ] Confirm the app is functional and matches the project description and demo.

## 2. GitHub repository

- [ ] Repository is on GitHub.
- [ ] Repository is public.
- [ ] Repository is accessible without special permissions.
- [ ] Repository root contains `.kiro/`.
- [ ] Relevant `.kiro/` files are committed, not only present locally.
- [ ] `.kiro/` is not excluded by `.gitignore`.
- [ ] Repository contains an OSI-approved open-source license.
- [ ] License is visible in the repository's GitHub About section, as required by the contest.
- [ ] README explains what the app does.
- [ ] README explains how to run the project locally.
- [ ] README identifies the deployed application and demo where appropriate.
- [ ] No secrets, private credentials, or personal data are committed.
- [ ] Repository does not contain misleading claims about unfinished features.

## 3. Live application

- [ ] Application is deployed to a public URL.
- [ ] URL opens without authentication or special access.
- [ ] Main experiment works in a clean browser session.
- [ ] Starter scenario works.
- [ ] Simulation controls work.
- [ ] Failure and recovery work.
- [ ] Metrics and event history are consistent with actual simulation behavior.
- [ ] No critical console errors or broken routes.
- [ ] App works on a typical laptop-sized screen.
- [ ] Optional services failing do not break the core experience.
- [ ] Final deployed version is the version shown in the demo.

## 4. YouTube demo

- [ ] Demo is uploaded to YouTube.
- [ ] Video is public and accessible to judges.
- [ ] Video is under 3 minutes.
- [ ] Video shows the actual application working.
- [ ] Video clearly explains the problem and product.
- [ ] Video shows the haunted theme and category fit.
- [ ] Video demonstrates one complete build/run/failure/recovery/replay story.
- [ ] Video does not show secrets or private information.
- [ ] Audio is understandable and visuals are readable.
- [ ] Demo URL is added to Devpost.

## 5. Devpost submission

- [ ] Project title and tagline are complete.
- [ ] Project description explains the problem, solution, and user experience.
- [ ] Category is correct.
- [ ] Live app URL is included.
- [ ] Public GitHub repository URL is included.
- [ ] Public YouTube demo URL is included.
- [ ] Kiro usage write-up is complete and factual.
- [ ] Technologies used are listed accurately.
- [ ] Screenshots show the final app.
- [ ] Submission is saved and successfully submitted before the deadline.
- [ ] Submission page is checked after submitting.

## 6. Kiro usage evidence

- [ ] `.kiro/steering/` documents are committed.
- [ ] Meaningful feature specs are committed.
- [ ] Actual Kiro workflows/features used are recorded in `kiro-usage-log.md`.
- [ ] Claims in the write-up match the repository and actual development history.
- [ ] Any hooks, agents, MCP tools, or property-based testing mentioned were genuinely used.
- [ ] Explain what Kiro contributed, what the developer reviewed/changed, and what was learned.

## 7. Final quality and rehearsal

- [ ] Run the application from a clean checkout or verify reproducible setup.
- [ ] Run the test suite.
- [ ] Run type checking and linting, if configured.
- [ ] Fix critical bugs and remove misleading placeholders.
- [ ] Rehearse the demo from a fresh start.
- [ ] Prepare a fallback demo path if a nonessential service fails.
- [ ] Verify all public links.
- [ ] Recheck the official rules and FAQ for updates.
- [ ] Submit with enough time to resolve upload or platform problems.
