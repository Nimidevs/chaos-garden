
# Chaos Garden — Kiro Usage Log

Record actual Kiro use as development happens. This file supports the hackathon write-up and helps us understand which Kiro workflows were useful.

**Do not invent entries, exaggerate what Kiro did, or list features merely because they exist.**

## How to use this log

After a meaningful Kiro-assisted session:

1. Add the date.
2. Name the Kiro feature or workflow used.
3. Describe the task in plain language.
4. Explain what Kiro produced or helped discover.
5. Record what the developer reviewed, changed, or decided.
6. Record the outcome, including failures or lessons where useful.

Keep entries short and factual. Link to a spec, commit, test, or file when practical.

## Write-up notes

A credible final Kiro write-up should answer:

- Why did you use Kiro for this project?
- Which Kiro workflows did you actually use?
- How did steering and specs influence the work?
- What did Kiro help implement or test?
- How did you review generated output?
- What is one meaningful example of Kiro improving or changing your development process?

Use this log as evidence. The final write-up should be concise and based on actual experience, not marketing language.
